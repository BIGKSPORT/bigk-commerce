## Important quote caveats
- Six price columns: 0–1, 1–3, 3–6, 6–10, 10–20, 20–31.5 kg. No price for >31.5 kg in quoted table.
- Check whether all amounts exclude VAT, fuel surcharge, peak, remote delivery, pickup, customs, insurance, oversized/weight surcharges, returns and other add-ons. Do not convert these to customer charges automatically.
- These rates cover many (but not all) European destinations; eligibility and services vary by location and postcode. B2C quote includes non-EU countries, which need separate customs/tax workflows.
- **NON-EU:** previous correspondence in June–July described failed labels and returned parcels for UK, Norway and Switzerland. HS code `62019300` was being applied indiscriminately across products in legacy integration, creating customs risk. Product-level tariff classification, origin, export declaration, return handling and DDP/DAP terms must be checked before enabling non-EU checkout.

## Suggested BIG K ® shipping architecture
1. Merchant/checkout country eligibility maintained in one shared server-side list, with *actual* confirmed service availability; never promise all Europe if account or routes are not operational.
2. Rate calculation keyed to destination country, billable weight and eligible DPD service; account for packaging, taxes and surcharges. Use a versioned internal rate card with effective dates and administrator approval.
3. Product-level customs fields (HS code, origin, weight, declarations) stored for every sellable SKU; do not inherit one HS code for all products.
4. Backoffice shipment workflow: paid order → address validation → package measurements → DPD label generation (stage first) → store label/tracking → handover/manifest → tracking updates → customer email; separate return labels and customs holds.
5. DPD technical API: official Shipper Webservice; stage and live credentials must be distinct, label generation sequential, obey API usage limits. Do not use retired Shopify-specific integration in the new standalone site.
6. Reconfirm whether shipment/return labels can be generated while account services are interrupted; do not issue billable live labels in development.
