# Hero, bag and mobile presentation
The fallback hero uses public ALPIN VEST P007's first product image, with the existing static vest image as fallback. Existing published campaign banners retain priority. Mobile puts the hero image first; the large slogan is visually reduced to accessible text. Decorative section numbers are removed. Full catalogue rendering and category order stay intact.
B10's campaign section retains the original warm background. Only sneaker catalogue photos gain contain fitting and white padding, preserving swipe, arrows and colour choices.
Both bag dialogs use the same component. The selected variant's assigned image takes precedence over the product image, including checkout thumbnails. Unknown cart lines are retained and labelled if catalogue loading fails. Quantities, IDs and local storage schema remain unchanged; the existing server checkout validates stock, prices and discounts.
The specialised Alpin page loads the existing localized public catalogue only when its bag opens. This adds one catalogue request on each bag opening, not on initial page load. The general storefront reuses its existing catalogue. No new dependency or paid service.
Suggestions use published, priced, pictured, in-stock styles, exclude families already in the bag, and show at most two. They link to size/colour selection and never add items automatically. No tracking or external personalization. Set NEXT_PUBLIC_BAG_UPSELL_ENABLED=false in Vercel and redeploy to disable suggestions without code changes. No environment variable is required to enable them.
No database migration. Rollback is a code revert of this release; existing cart data and owner merchandising documents are not rewritten. Tests use a disposable SQLite fixture and validate chosen-colour photos, sold-out/draft exclusion, responsive presentation, both bag dialogs, existing mobile product navigation, and checkout.
