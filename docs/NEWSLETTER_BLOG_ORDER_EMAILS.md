# Newsletter, journal and order workflow

Public signup is in the footer and at `/newsletter`. The checkbox is unchecked. A requested email does not create marketing permission: the recipient must explicitly confirm the private email link. Link scanners/GET requests do not subscribe or unsubscribe. Confirmation records dated, versioned consent in the existing customer/marketing workspace. Opt-out invalidates old confirmation links; later rejoining needs a new email proof. An account opt-out after a request also blocks that old request. Unconfirmed requests that never had subscribed/unsubscribed history are removed after 30 days by maintenance. No marketing campaign is sent or scheduled here.

Confirmed contacts appear under Customers and Marketing. Newsletter counts appear in Marketing. Existing archived contacts and external Brevo suppression must still be respected: the existing consented CSV handoff remains manual. This work does not claim automatic Brevo contact sync or delivery. Order/account messages remain separate from marketing permission.

`/blog` displays only published articles. Admin → Blog supports new drafts, private previews, cover selection from the existing photo library, text editing, publication and archiving. The first series-guide article is published; label-care and size-guide articles start as drafts. Existing article changes are never overwritten by rerunning the seed. Already-published URLs stay stable. Plain paragraphs, `##` headings and `-` lists render as escaped React text, never raw HTML. Public articles have canonical/Open Graph metadata and BlogPosting data; sitemap inclusion follows the store’s indexing gate.

Orders → Manage order includes a private paid-order packing slip, carrier, optional HTTPS tracking link and a packing confirmation. Dispatch still requires a verified paid order and no unresolved withdrawal request. Dispatch queues one shipment message; retries cannot fulfil the same order twice. No inventory is deducted a second time. Packing slips are not invoices. This remains a manual carrier workflow: it does not purchase labels or create pickups.

Connections → Order emails shows pending/accepted/needs-review counts, the latest 100 messages, owner-only labelled sample sends and retry controls for unsent messages. Accepted means provider acceptance, not proven inbox delivery. Review ambiguous provider attempts before manually retrying. Paid settlement, dispatch and withdrawal submissions schedule delivery after the DB changes commit. A protected Vercel Cron job sweeps retries and reservation expiry every five minutes; the existing Vercel team is Pro. `CRON_SECRET` must be a sensitive Production variable. Both cron and manual retries retain the existing lease/backoff and stable provider idempotency keys. Campaign delivery is not enabled.

The job endpoint’s POST test action can only send the fixed confirmation/shipping sample to `ADMIN_OWNER_EMAIL`. It creates no order, payment, stock movement or shipment. The real tests authorized for this release use team@bigk.be only.

Additive production/staging SQL: `supabase/production/newsletter-blog.sql`; no existing product, order, inventory, customer profile or consent records are rewritten. SQLite creates the same tables for disposable fixtures. Verification includes SQLite and PostgreSQL permission/consent/publication tests, existing commerce tests, and desktop/mobile browser journeys through signup, confirmation, unsubscribe, draft/public article safety, packing slips and dispatch queueing.

Remaining launch requirements are unchanged: final approved legal policies and contract information, accurate sellable stock/prices, correct tax/invoices, a live payment/refund test, recovery/monitoring evidence and operational shipping arrangements. Keep checkout disabled until these pass.
